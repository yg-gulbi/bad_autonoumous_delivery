# 헤드리스 크롬 화면 캡처가 끝나지 않음 (SSE 화면)

- 프로젝트: bad_ws · PART 01 관제 화면 (`src/part1_ui_dashboard`)
- 발생일: 2026-11-19
- 기록일: 2026-11-19
- 상태: 해결 (작업 도구)
- 관련 파일·Issue·PR·커밋: `docs/part3/ui/stage4j-report.md`, `docs/part3/ui/screens/4j-*.png`

## 1. 문제정의

### 기술적으로 관찰한 사실

- 4J 화면 캡처에서 `google-chrome --headless=new --virtual-time-budget=8000 --screenshot=… http://localhost:8097/`가 60초 제한 안에 끝나지 않았고(종료 코드 124) 파일도 만들지 않았다.
- `--virtual-time-budget` 없이 찍으면 실시간 상태가 오기 전 빈 화면이 찍힌다.

### 원인

- 확인되지 않음(가설): 관제 화면은 `/events` SSE 연결을 계속 열어 둔다. 가상 시간 예산은 진행 중인 네트워크 요청이 없을 때 흘러가므로 끝나지 않는 것으로 보인다.

## 2. 해결방법 안들 설정

| 해결안 | 선택 또는 보류 이유 | 결과 |
| --- | --- | --- |
| 캡처용으로 화면이 SSE를 안 쓰게 바꾸기 | 화면 코드를 시험 도구 때문에 바꾸지 않는다 | 미실행 |
| pip로 Playwright·websocket 설치 | pip 금지 | 미실행 |
| 표준 라이브러리만으로 DevTools 프로토콜 클라이언트를 짜서 이동 → 대기 → 캡처 | 설치 없이 되고, 페이지 스크립트 오류도 함께 모을 수 있다 | 선택 |

## 3. 해결방법 실행

- AI가 작업용 스크립트(작업 폴더의 `cdp.py`, 저장소에 넣지 않음)로 크롬을 `--remote-debugging-port`로 띄우고, 웹소켓 핸드셰이크·프레임을 직접 처리해 `Page.navigate`, `Page.captureScreenshot`을 보냈다. 페이지에 오류 수집 스크립트를 먼저 넣어 `window.__errors`를 확인했다.

### 검증

- 실행한 확인: 격리 mock에서 4장 캡처, 매번 페이지 스크립트 오류 0건.
- 실제 결과: `docs/part3/ui/screens/4j-01`~`04` 저장.
- 남은 한계: 원인은 가설이다.
