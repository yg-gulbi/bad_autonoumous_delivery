## 1. 문제정의

### 기술적으로 관찰한 사실

사용자는 노트북의 'VIDEO_PATH를 원본 RGB 영상으로 지정하면…' 문구를 보고 실행이 안 된다고 알렸다. 저장된 출력에서 모델 4개 다운로드는 성공했지만 데이터셋 셀은 catalog 모드이고 VIDEO_PATH는 환경변수 미설정 시 None이었다. 패키지와 기존 실험 폴더·Downloads의 ZIP에서 입력 영상을 찾지 못했다. 런타임 traceback은 저장되어 있지 않았다.

### 원인

모델 다운로드와 입력 영상 다운로드가 분리되어 있었고, 데이터셋을 받아도 다음 단계에 경로를 자동 전달하는 코드가 없었다. 모델 가중치를 받은 것만으로 추론 영상은 준비되지 않는다.

## 2. 해결방법 안들 설정

| --- | --- | --- |
| 사용자가 VIDEO_PATH를 직접 입력 | 사용자의 자동 연결 요청을 충족하지 못함 | 보류 |
| 원본 탐색 → 없으면 다운로드 → 압축 해제 → 자동 선택 | 실제 입력 파일을 다음 셀로 전달 | 선택 |

## 3. 해결방법 실행

AI가 input_video.py를 추가하고 노트북 기본 동작을 auto_video로 변경했다. 로컬 data와 지정 데이터 폴더에서 영상이 발견되면 다운로드 없이 재사용한다. 없으면 실제 제공자 목록의 원본 RGB 침대 MP4/ZIP 후보를 사용하고, 다운로드가 끝난 실제 경로를 VIDEO_PATH에 전달한다. 첫 프레임은 OpenCV로 읽어 미리보기에 PyAV가 필수인 문제도 줄였다. ROI/GT 검수 상태는 자동 변경하지 않는다.

현재 도구로 FallVision 공식 페이지를 조회하면 봇 확인 문구가 반환됐다. 샌드박스의 Python HTTP 요청은 ConnectionError로 실패했다. 따라서 실제 원본 영상 다운로드 성공으로 기록하지 않는다. 다운로드 실패 상태·공식 주소·로컬 파일 연결 폴더를 명시한다.

### 검증

- 기존 원본 영상 자동 선택, 가공 영상 제외, 모델 파일을 영상으로 오인하지 않음 확인.
- 모의 제공자 다운로드·ZIP 해제 결과가 자동 선택되고 다음 실행에 재사용됨 확인.
- 제공처 실패는 입력 없음으로 보고하며 성공 영수증을 만들지 않음 확인.
- 실제 AVI를 OpenCV로 읽어 첫 프레임 표시 경로 검증.
- 원본 RGB 병상 영상 확보·ROI 검수·성능 측정은 미완료.

### 이미지 한 장으로 범위 변경

사용자가 영상 대신 다운로드한 이미지 한 장만 전달하도록 요청했다. AI가 Roboflow Bed Exit 공개 모델 페이지에서 제공한 실제 예시 이미지의 원본 JPG를 다운로드했다. 파일은 `src/part5_bed_exit/data/sample/bed_exit_sample.jpg`이며 1920×1080 BGR uint8로 읽힌다. 소스 URL·SHA256·작성자·라이선스는 인접 source.json에 기록했다. 파일은 data/ 아래에 있어 Git에서 제외된다.

별도 part5_single_image.ipynb는 이 파일을 자동 연결하고 네 메서드에 한 번씩 전달한다. 이미지 전용 예시 ROI와 환자 초기 선택 박스를 사용하며 ROS의 다수결·카메라 오류 정책은 변경하지 않는다. 첫 실행에서 MediaPipe는 신뢰도 높은 관절로 만든 작은 박스가 큰 초기 선택 박스와 충분히 겹치지 않아 patient_unassociated를 반환했다. 샘플에서 실제 보이는 몸통 영역으로 초기 선택 박스를 수정했다. 인식 임계값이나 미검출 오류 정책은 바꾸지 않았다.

수정 후 전체 의존성이 설치된 검증 환경에서 이미지 전용 노트북의 모든 Python 셀을 순서대로 실행했다. 같은 JPG를 네 실제 사전학습 모델에 전달해 모두 Python bool 반환을 확인했다. 예시 ROI 기준 raw 결과는 네 방법 모두 True였다. 단일 이미지 연결 검사이며 병상 이탈 정확도·시간 지표·5프레임 판정의 검증 결과가 아니다.

## 4. 경험의 재해석

### 내가 실제로 경험하고 느낀 것

사용자는 VIDEO_PATH 안내 문구를 보고 실행이 안 된다고 보고했고 다운로드한 곳에 자동 연결해 달라고 요청했다.

### AI 해석·제안

설치·모델 준비·입력 준비·추론을 각각 명확한 결과로 표시하면 셀이 실행됐지만 동작이 없는 상황을 설명할 수 있다.
