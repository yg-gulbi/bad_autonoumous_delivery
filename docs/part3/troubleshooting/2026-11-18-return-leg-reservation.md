# 연속 구간에서 통로 복귀 예약이 이전 구간과 함께 해제됨

bad_ws PART 03 · 2026-11-18 발생 및 기록 · 해결

## 1. 문제정의

환자 이송 테스트 26에서 Robot A가 통로를 빠져나와 C에 도착하고, 1초 이내에 픽업 확인을 받아 A행 복귀 구간을 허가받았다. 이전 구간의 해제 타이머가 끝나면 복귀 허가가 유효한데도 통로 보유자 목록에서 Robot A가 사라질 수 있었다. 두 구간이 같은 로봇의 점유 기록 하나를 사용한 것이 원인이었다.

## 2. 해결방법 안들 설정

| 해결안 | 선택 근거 | 결과 |
|---|---|---|
| 기존 점유에 다음 구간 예약을 표시 | 이전 구간의 물리 해제 조건과 새 구간의 허가를 동시에 추적할 수 있음 | 적용 |

## 3. 해결방법 실행

로봇이 자원 밖에서 같은 자원을 다시 허가받으면 보유 기록에 복귀 예약을 남긴다. 해제 여유 밖에서 1초가 지나면 해당 로봇의 상태를 `OCCUPIED`에서 `GRANTED`로 옮긴다. 다시 들어오면 `OCCUPIED`가 되고, 들어오기 전에 구간을 취소하면 허가를 반납한다. [자원 관리자](../../../src/part3_fleet_manager/part3_fleet_manager/core/resource_manager.py)

### 검증

가짜 시계로 이전 구간의 해제 시점을 넘긴 뒤에도 Robot A가 통로 보유자로 남는지 확인했다. 복귀 중 두 로봇이 통로를 실제로 점유하고 두 임무와 후속 배차가 진행되는 테스트가 통과했다. [테스트 26](../../../src/part3_fleet_manager/test/test_fleet_core.py)

## 4. 경험의 재해석

사용자 경험 미기록. 이번 사례에서는 각 구간의 MOVE 명령과 구간 사이의 보유자 목록을 함께 검사해야 예약 소실을 발견할 수 있었다.

## 5. 정리

같은 로봇이 즉시 되돌아올 때는 복귀 허가, 이전 점유 해제, 재진입 시점의 상태를 순서대로 확인한다.
