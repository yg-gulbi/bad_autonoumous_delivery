# 복귀 취소 확인 전에 다음 임무의 MOVE가 나가는 문제

bad_ws PART 03 · 2026-11-18 단계 2b 당시 기록

**단계 3D 갱신.** 복귀 구간에서 CANCEL을 보낸 뒤 홈 ARRIVED, 종료 STATE, 취소 확인 또는 R1의 CANCEL 거절이 오면 즉시 새 구간으로 넘어간다. 3초 동안 증거가 없을 때만 NAV_FAILED 카드를 연다. 아래 본문은 변경 전 동작을 기록한다. [현행 규칙](../BRIEF.md#51-mission--임무와-로봇-상태머신) · [회귀 테스트 29](../../../src/part3_fleet_manager/test/test_fleet_core.py)

## 1. 문제정의

가짜 시계로 복귀 중인 Robot A에 새 CALL을 배정했다. 0.3초에 관제가 `CANCEL`을 보냈고, 0.4초에 같은 복귀 구간의 `ARRIVED`만 도착했다. 수정 전 코드에서는 이때 이미 `MOVE A 1 id=L-0002-1`이 나갔다. 임무 상태머신이 복귀 도착과 취소 확인을 같은 분기로 처리한 것이 원인이었다.

## 2. 해결방법 안들 설정

| 해결안 | 선택 근거 | 결과 |
|---|---|---|
| 홈 도착을 위치에 반영하고 해당 복귀 구간의 취소 확인까지 새 MOVE 보류 | 로봇의 실제 위치와 명령 처리 결과를 모두 보존한다. | 적용 |

## 3. 해결방법 실행

`ARRIVED`를 받으면 홈 도착을 기록한다. 같은 복귀 구간의 `MISSION_CANCELED` 또는 `STATE=CANCELED`가 도착해야 다음 임무를 출발시킨다. 홈 도착을 보고한 뒤에도 취소 확인이 없으면 기존 `robot_link.accept_timeout_s`를 사용해 `NAV_FAILED` 카드를 연다. 운영자는 카드에서 복귀 구간을 종료할 수 있다. [임무 상태머신](../../../src/part3_fleet_manager/part3_fleet_manager/core/mission.py)

### 검증

수정 전 코드로 회귀 테스트를 실행했을 때 두 경우 모두 0.4초 시점에서 실패했다. 수정 후에는 늦은 취소 확인이 오는 경우와 끝내 오지 않는 경우가 모두 통과했다. 후자는 카드에서 운영자가 복귀 구간을 종료한 뒤 다음 tick에서 새 임무가 출발했다. [가짜 시계 테스트](../../../src/part3_fleet_manager/test/test_fleet_core.py)

## 4. 경험의 재해석

사용자 경험 미기록. 이번 경합은 가짜 시계로 메시지 순서를 지정해 재현했다. 정상 mock 실행에서 관측된 순서는 [시나리오 5](../stage3-scenarios.md#5-call-세-건--수령-완료-복귀-중-재배정)에 있다.
