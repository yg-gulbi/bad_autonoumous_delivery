# 첫 장애물 분류 응답에서 관제 노드가 종료됨

bad_ws PART 03 · 2026-11-18 발생 및 기록 · 해결

## 1. 문제정의

시나리오 4에서 로봇은 정상적으로 촬영을 요청했다. 첫 응답을 기록하는 tick에서 `ResourceManager.record() got multiple values for argument 'kind'` 예외로 관제 노드가 종료됐다. 응답이 없는 경우에도 시간 초과 결과를 기록할 때 같은 예외가 재현됐다.

## 2. 원인과 해결안

기록 함수의 첫 번째 인자와 분류 결과의 상세 필드가 모두 `kind`였다. 이벤트 종류를 받는 함수 인자를 `event_type`으로 바꿨다. 이로써 발행 형식의 바깥 `type`에는 이벤트 이름을, 안쪽 `detail.kind`에는 장애물 종류를 각각 보존한다.

## 3. 실행과 검증

테스트 39에서 응답 수신, 무응답, 늦은 응답을 각각 실제 fleet tick으로 검증했다. ROS mock과 브라우저에서 사람·의자·미검출 각각의 결과, 카드, 막힘 해제 및 두 로봇의 대기 복귀도 확인했다. [시나리오와 캡처](../ui/stage3o-report.md)

## 4. 경험의 재해석

사용자 경험 미기록. 파서 단위 테스트는 분류 결과를 받아들이지만, 이 오류는 해석한 값을 이벤트로 저장할 때 발생했다.

## 5. 정리

회귀 검증은 `OBSTACLE_RESULT`의 종류와 상세 정보, 같은 tick의 자원 상태와 카드까지 확인한다.
