# 격리 시험 PC에서 발견 서버가 UDP 포트를 열지 않음

bad_ws 단계 4P · 2026-11-18 발생 및 기록 · 해결

## 1. 문제정의

격리 시험 PC에서 강의실 명령의 주소와 포트를 루프백 값으로 바꿔 실행하자 `Unknown arguments`가 나왔고 UDP 포트가 열리지 않았다. 강의실에서 성공한 실행 파일은 `/usr/bin/fastdds`, 시험 PC에 설치된 실행 파일은 `/opt/ros/jazzy/bin/fastdds`였다.

## 2. 해결안

시험 PC에 설치된 `fast-discovery-server --help`에서 UDP 주소와 포트의 인자가 각각 `-l`과 `-p`임을 확인했다. 현장 문서에는 강의실에서 확인한 명령을 유지했다.

## 3. 실행과 검증

발견 서버·슈퍼 클라이언트 환경 변수를 해제하고, ROS 발견 범위를 LOCALHOST, 도메인을 87로 둔 루프백 전용 시험 환경에서 아래 명령을 실행했다.

```bash
/opt/ros/jazzy/bin/fast-discovery-server -i 0 -l 127.0.0.1 -p 31947
```

preflight의 포트 검사에 이 주소를 인수로 주자 UDP 소유자 `fast-discovery-server`가 확인됐다. 서버를 종료한 뒤 같은 검사는 ‘UDP 수신 포트 없음’을 반환했다.

## 4. 경험의 재해석

시험에서 관측한 차이는 실행 파일 경로와 명령행 옵션이었다. 사용자가 강의실에서 확인한 결과와 격리 PC의 결과는 각각 해당 설치에 적용된다.

## 5. 정리

포트가 열리지 않을 때는 설치된 실행 파일의 경로, 도움말과 시작 로그를 먼저 확인한다. [현장 명령](../REAL_TEST.md)
