# 취소 완료 보고 두 건이 복귀 임무를 실패 처리함

bad_ws PART 03 · 2026-11-18 발생 및 기록 · 해결

## 1. 문제정의

막힘 카드에서 되돌아가기를 선택한 뒤 같은 tick에 `STATE CANCELED`와 `STATUS MISSION_CANCELED`가 들어왔다. 첫 보고로 취소가 확정됐지만, 두 번째 보고가 예상하지 않은 취소로 처리됐다. 그 결과 복귀 MOVE를 보내야 할 때 `FAULT`와 카드가 발생했다.

## 2. 해결방법 안들 설정

| 해결안 | 선택 근거 | 결과 |
|---|---|---|
| 취소 확인 시점에 해당 PART 04 임무 ID의 처리를 종료 | 두 형식 중 먼저 도착한 보고로 취소를 확정하고 다음 구간을 별도로 추적할 수 있음 | 적용 |

## 3. 해결방법 실행

취소를 처음 확인할 때 해당 로봇의 이전 임무 ID를 종료 목록에 넣었다. 이후 같은 ID로 도착한 이벤트는 복귀 임무에 전달되지 않는다. [로봇 프로토콜](../../../src/part3_fleet_manager/part3_fleet_manager/core/robot_protocol.py)

### 검증

두 JSON 보고를 같은 tick에 넣은 뒤 이전 구역행 MOVE가 한 번 발생하고, 복귀 후 운영자가 원래 목적지행 구간을 재시도할 수 있음을 확인했다. [막힘 카드 복귀 테스트](../../../src/part3_fleet_manager/test/test_fleet_core.py)

## 4. 경험의 재해석

사용자 경험 미기록. 주기 상태와 상태 변경 이벤트는 서로 다른 입력이지만 동일한 취소 한 건을 확인할 수 있다.

## 5. 정리

취소 후 경로를 바꾸는 경우에는 명령 순서와 함께 이전 임무의 중복 보고도 검사한다.
