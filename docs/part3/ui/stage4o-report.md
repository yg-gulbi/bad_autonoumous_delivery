# 4O 두 로봇 함께 계획하기 (PLAN)

ac58e60("4O WIP", 칸 예약 엔진)에서 시작했다. 허가 비교·선점과 무작위 시험을 통과시키려고 붙인 상황별 보정을 모두 걷어내고, 두 로봇을 시공간 A*로 함께 계획한 뒤 그 순서를 ADG로 지키는 방식으로 바꿨다. 모드 이름은 `traffic.mode: LEGACY | PLAN`이고 기본값은 LEGACY, 실행 인자는 `traffic_mode:=PLAN`이다. [결정 D-43~47](../DECISIONS.md) · [사양 5.3a](../BRIEF.md)

동작은 그래프, 충돌 쌍, 비용에서만 나온다. 계획기(`core/planner.py`)와 그래프(`core/plan_graph.py`)에는 구역 이름이나 장면 이름이 없다.

## 1. 지점 그래프

`fleet.yaml`의 `traffic.segments`·`links`(칸 지도)와 `traffic.graph`에서 만든다. 코드 안의 지도(`build_default_map_specs`)는 지웠다.

```
        A1   A2                    D1   D2
          \  |                      |  /
           ─────── HALL_TOP (위쪽 홀 입구) ───────
                         │
                  CORRIDOR_TOP_1          복도 위쪽: 2칸 (one_way)
                         │
                  CORRIDOR_TOP_2
                         │ ╲
 B1 ─┬─ ROOM_B ── DOOR_B ─┴── CROSSROAD ── DOOR_E ── ROOM_E ─┬─ E1
 B2 ─┘    (방 안)  (single)    (single)     (single)  (방 안) └─ E2
                         │
                  CORRIDOR_BOTTOM_1       복도 아래쪽: 3칸 (one_way)
                  CORRIDOR_BOTTOM_2
                  CORRIDOR_BOTTOM_3 ── F2
                         │
           ─────── HALL_BOTTOM (아래쪽 홀 입구) ───────
          /    |            |      \
        C1    C2           F1 ── DOCK_B (약품 운송 로봇 도크)
```

| 종류 | 지점 | 기준 |
|---|---|---|
| 자리 12개 | A1·A2 … F1·F2 | 칸 지도의 자리 칸(원)과 `slots` 좌표 |
| 도크 | DOCK_B | `robots.robot_b.dock` |
| 교차로·문 | CROSSROAD, DOOR_B, DOOR_E | 칸 지도의 single 칸 |
| 방 안 | ROOM_B, ROOM_E | 칸 지도의 shared 칸 |
| 홀 입구 | HALL_TOP, HALL_BOTTOM | `graph.points` 좌표 |
| 복도 칸 | CORRIDOR_TOP_1·2, CORRIDOR_BOTTOM_1~3 | `graph.corridor`의 두 칸을 `cell_m` 0.5 m로 자동 분할 |

- 지점 사이 경로는 `route_planner` 경로를 0.02 m 간격으로 표본 삼아 지점 영역으로 자른 실제 선이다. 걸리는 단계 수는 거리 ÷ `plan_speed_mps`(미설정 시 `mock.speed_mps` 0.2) ÷ `plan_step_s` 0.5를 올림한다. 끝점 사이 경로 156개, 6~74단계(중앙값 45).
- 충돌 쌍은 두 위치의 선 사이 거리로 계산한다. 둘 다 움직이면 `proximity_stop_m` 0.6 m, 한쪽이 자리에 서 있으면 `slot_stop_m` 0.45 m, 둘 다 서 있으면 충돌이 아니다. 여기에 복도·교차로·문의 대수 제한(single, 복도는 같은 방향만 함께 쓰는 one_way)을 더한다. 지도 고정 조각 733개 사이 268,278쌍 가운데 78,108쌍이 충돌이다.

## 2. 계획과 실행

- 상태는 (A 위치, B 위치, 시간)이다. 한 단계는 `plan_step_s` 0.5초. 행동은 다음 지점으로 가기, 기다리기, 서 있을 때 다른 자리로 가는 새 MOVE다. 두 로봇이 모두 조각 안을 달리는 동안은 정할 것이 없으므로 다음 조각 경계까지 건너뛴다. 충돌 쌍과 맞바꾸기(같은 순간 서로의 이전 위치로)는 허용하지 않는다.
- 비용은 Σ `level_weights[Level]`({1: 1, 2: 3, 3: 9}) × 도착 시각이다. 임무 없는 로봇의 목표는 지금 자리이고 가중치는 `idle_weight` 0.5다. 목표 자리는 1번·2번 모두 후보이고 같으면 1번이다.
- 정지선(`stop_margin_m` 0.8 m) 안의 지점은 이미 정해진 것으로 둔다. 주행 중 로봇의 경로는 정지선에서 한 번 더 잘라 그 앞까지만 고정한다(D-47). 지나온 지점으로 되돌리지 않는다.
- 세 대 이상이거나 시간 한도(`plan_limit_ms` 1000 ms)를 넘으면 Level 순서로 한 대씩 계획한다(반대 순서도 시도). 그래도 길이 없는 로봇은 제자리에 둔다. 이 경우 `PLAN_UPDATE` 문장에 "Level 순 계획으로 대신 (…)"이 붙는다.
- 실행은 ADG다. 충돌하는 두 위치에는 계획 순서대로 선후를 두고, 뒤 로봇은 앞 로봇이 그 위치를 `clear_margin_m` 0.2 m 지나 `clear_hold_s` 동안 벗어날 때까지 정지선에서 PAUSE한다. 풀리면 RESUME. PART 04에는 MOVE·PAUSE·RESUME·CANCEL만 보낸다.
- 다른 자리로 가는 MOVE는 "길 비켜 주는 중"이다(`PLAN_YIELD_MOVE`). 그 자리 도착은 정류장 도착이 아니어서 확인 대기와 정지 기록을 남기지 않고 다시 계획한다.
- 다시 계획: 새 구간 요청, 취소, Level 상향 재접수, 구간 도착, 계획보다 `replan_delay_s` 5초 넘게 늦음, 안전 정지 해제, 연결 복구, 비켜선 자리 도착. 취소는 새 목표다(D-46). 연결이 끊긴 로봇과 CANCEL 확인 전 로봇은 칸을 계속 쥐고 남은 MOVE 경로를 막은 것으로 둔다.
- 화면: 로봇별 계획 지점과 가는 계획 경로 선, ADG에서 나온 대기 이유("교차로: 약품 운송 로봇이 지나간 뒤"), 기록과 로그의 `PLAN_UPDATE`(이유·시간·비용)·`PLAN_WAIT`·`PLAN_YIELD_MOVE`.

## 7. 계획 시간

| 측정 | 계획 수 | 평균 | 중앙값 | 상위 5% | 상위 1% | 최대 | 두 대 동시 계획 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 계획기 단독: 모든 자리 쌍(다른 구역끼리 120쌍) × Level 조합 9 (`test_4o_plan.py`) | 1,080 | 46.9 ms | — | 250.7 ms | — | 454.9 ms | 1,080 (100%) |
| 무작위 시험 시드 0~29 안의 실제 다시 계획 | 4,942 | 3.4 ms | 1.6 ms | 10.9 ms | 35.9 ms | 218.1 ms | 4,729 (95.7%) |

- 평소 한도 200 ms는 평균으로, 최대 한도 1 s는 최대로 지켰다. 단독 측정의 상위 5%는 200 ms를 넘는다. 무작위 시험에서 200 ms 초과는 4,942회 중 1회, 1 s 초과는 0회다.
- Level 순 계획 213회(4.3%)는 모두 시간 초과가 아니라 "경로 없음"이었다. 시드 0~9에서 분류하면 69회 중 61회는 상대가 CANCEL 확인 전, 7회는 안전 정지라 그 로봇의 남은 MOVE 경로를 막은 것으로 둔 순간이다. 길이 없는 로봇은 제자리에서 다음 계획을 기다린다.
- 다시 계획한 이유: 구간 종료 2,489, 새 구간 요청 1,745, 비켜선 자리 도착 257, 안전 정지 해제 244, 계획보다 늦음 176, 시작 30. 같은 30개 시드에서 비켜서기 MOVE 362회, 계획 순서 대기 1,481회.

|---|---|---|
| `fleet_core.__init__` | 링크의 `resend_controls` = PLAN | RESUME·CANCEL 3초 재전송은 PLAN에서만 (D-43) |
| `fleet_core.tick` | 같은 tick에 `mission.plan()`을 한 번 더 부르고, 계획 결과의 `retarget`(다른 자리로 바꿀 로봇)·`arrived`(이미 목표 자리에 선 로봇) 처리 | 도착·취소로 끝난 구간을 계획 전에 다시 요청한다. 서 있는 로봇에 MOVE를 보내면 근접 규칙에서 "주행 중"이 된다 |
| `fleet_core._stall_tick` | `traffic.plan_hold(robot)`이면 멈춤으로 세지 않음 | 계획 순서 대기는 막힘이 아니다. LEGACY는 항상 False |
| `fleet_core` 운영자 명령 | 점유 불명 해제 대상에 칸 이름 허용 | PLAN의 칸이 UNKNOWN이 될 수 있다 |
| `mission._interruptible_return` | `target_override`(이전 구역으로 물러나기)는 끼어들 수 없는 복귀 | ac58e60의 조건을 PLAN에만 (D-43) |
| `mission._at_home_slot` | PLAN은 MOVE를 끝낸 자리(`parked_zone`)로 판정 | 길 위에 선 로봇을 자리에 선 것으로 보지 않는다. LEGACY는 `None`이라 기존 거리 판정 |
| `mission.granted` | MOVE 목적지를 계획의 첫 자리(`move_target`)로 | 비켜설 자리로 먼저 보낸다 (D-45) |
| `mission.received` ARRIVED | `traffic.arrived_aside`이면 정류장 도착이 아님 | 비켜선 자리 도착 (D-45). LEGACY는 항상 False |
| `mission.retarget` | 계획이 다른 자리로 바꾸면 CANCEL 후 같은 구간을 다시 요청 | 운영자 재시도와 같은 경로 |
| `mission.cancel` | `traffic.cancel_policy` — LEGACY는 E-423(복도 안 취소 거절) 그대로, PLAN은 즉시 | 취소는 새 목표 (D-46) |
| `mission.wire_step` | RESUME 의도(`resume_due`)를 STATE `MOVING`까지 유지 | PLAN은 응답 없는 RESUME를 다시 보낸다 |
| `collision.CollisionControl` | `enable_zone_traffic=False`면 같은 구역 출입 순서를 끈다 | 출입 순서도 계획이 정한다. 0.9 m 출발 확인과 근접 정지는 그대로 |
| `config.effective_return_after_cancel` | 미설정 시 PLAN true | D-46 |
| PLAN 전용 클래스 | `PlanTraffic`, `PlanManager`, `PlanGraph`, `Planner`, `SegmentBoard` | 모드 전환으로만 만든다 |

## 9. 이번 단계에서 고친 것

- **시드 216**: 연결이 끊긴 2초 사이에 계획이 로봇을 다른 자리로 바꾸며 보낸 CANCEL이 사라졌다. 로봇은 그대로 달렸는데, 다음 계획이 그 로봇을 "서 있음"으로 보고 아직 안 들어간 복도 위쪽 칸 예약을 반납해 예약 없는 진입이 생겼다. CANCEL 확인 전이거나 연결이 끊긴 로봇은 칸을 계속 쥐고 남은 MOVE 경로 전체를 막은 것으로 둔다(D-46).
- **정지선 자르기**: 16:07:09에서 A는 교차로까지 1.26 m라 정지선 앞에서 설 수 있었다. 그러나 "정지선 안에서 시작하는 칸"을 칸 끝까지 고정해 A가 교차로 바로 앞(0.59 m)을 막는 것으로 계산됐고, B(L3)가 B2로 비켜섰다가 41.4 s 만에 도착했다. 경로를 정지선에서 잘라 19.0 s로 줄었다(D-47).
- **계획 캐시**: 위치마다 만든 경로·조각과 거리·충돌 캐시가 계속 늘었다. 그래프를 관리자마다 복사하고 지금 계획이 쓰지 않는 것을 지운다. 매 계획마다 지우는 시험(시드 3·39·216)도 통과했다.

## 11. 남은 위험

- **실제 속도**: 계획 시간은 0.2 m/s 기준이다. 실제가 다르면 순서는 ADG가 지키지만 늦어지는 쪽이 생기고 "계획보다 늦음" 다시 계획이 잦아진다. `plan_speed_mps`를 실제 값으로 바꿔야 한다.
- **PAUSE 지연**: 정지선 0.8 m는 0.2 m/s에서 4초 거리다. PAUSE가 그 안에 먹히지 않으면(재전송 1.5초 간격이 두 번 넘게 실패하거나 실제 속도가 더 빠르면) 로봇이 다음 지점에 들어가 ADG 순서가 깨진다. 그때는 근접 정지가 마지막 방어선이다.
- **Nav2가 경로를 벗어남**: 계획 경로는 `route_planner` 선이다. Nav2가 다른 선으로 가면 충돌 쌍 계산과 실제 거리가 다르다. 16:09:59 변형 2의 비켜서기는 계획상 "교차로까지 갔다가 되돌아옴"인데 실제 Nav2는 그 자리에서 돌아선다(계획이 더 보수적인 쪽).
- **MOVE 시작 지연**: `move_start_s` 1.0초는 mock 기준 추정이다. 실제 수락이 3초 가까이 걸리면 서 있던 로봇의 출발이 계획보다 늦다.
- **Level 순 계획**: 최적이 아니다. 무작위 시험에서 계획의 4.4%가 이 경로였고, 대부분 상대가 CANCEL 확인 전이라 남은 경로를 막은 순간이다. 실제 CANCEL 확인이 늦으면 그동안 다른 로봇이 서 있는 시간이 길어진다.
- **세 대 이상**: Level 순 계획만 쓴다. 두 대 기준으로만 시험했다.
