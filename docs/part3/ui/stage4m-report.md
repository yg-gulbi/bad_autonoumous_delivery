# 4M · 침상 이탈 신호 깜빡임과 경보 팝업 중복

3분간 침상 신호가 깜빡이는 동안 **침상 이탈 이벤트 1회, 대상 로봇 정지 명령 1회, 경보 팝업 1개**를 확인했다. 정상 신호가 1초간 이어지자 해제 이벤트가 한 번 발생했고, 운영자 재개 입력까지 로봇은 정지 상태를 유지했다.

## 현장 기록과 적용 기준

팀이 제공한 mu-03의 12:55~12:59 집계에서 이탈과 해제는 각각 35회, 감시 경고는 29회, 감시 끊김은 3회였다. 같은 구간의 정지와 재개는 각각 3회와 1회였다. 이번 검증은 이 기록의 간격을 반영한 가짜 시계 입력으로 진행했다. 현장 DB 원본을 재생하거나 실기 로봇을 운행하지 않았다.

| 결정 | 적용한 기준 |
|---|---|
| D-38 · 이탈 해제 | 첫 `True`에서 즉시 이탈을 기록한다. 첫 `False`부터 수신 시각을 재고, 1.0초 이상 지난 정상 프레임에서 해제를 기록한다. 중간에 `True`가 오면 정상 확인을 다시 시작한다. `/fleet/state`의 값과 UI·서비스의 재개 거절에 같은 기준을 쓴다. |
| D-39 · 화면 경보 | 침상 이탈·감시 끊김·범퍼·막힘·연결 끊김·장애 경보는 종류와 대상 로봇 집합이 같으면 열려 있거나 대기 중인 경보의 시각만 갱신한다. [확인] 뒤 같은 원인과 대상의 새 `PAUSE`가 오면 다시 연다. 정지 사유가 있는 동안 상황 줄은 계속 표시한다. |
| 감시 복구와 경고 | `BED_MONITOR_BACK`에서 미확인 LOST 경보를 화면과 대기열에서 제거한다. 다른 종류의 대기 경보는 이어서 표시한다. `BED_MONITOR_WARN` 토스트의 30초 제한은 문구별로 화면 수신 시간을 기준으로 적용한다. |

연속 정상 시간을 계산할 때 기존 감시 지연 기준인 `warn_s`(기본 1.0초) 이상의 수신 공백은 제외했다. 예를 들어 정상 프레임 한 장 뒤 신호가 끊기면 그 시간만으로는 이탈이 해제되지 않는다. ROS 서비스가 tick 사이에 들어오면 대기 중인 입력까지 같은 규칙으로 미리 판정하고, 이벤트와 명령은 tick에서 한 번만 처리한다. 경보 확인 상태는 현재 열린 브라우저 페이지에 유지되며 메뉴 이동과 이벤트 스트림 재연결에도 유지된다. [결정 기록](../DECISIONS.md)

## 가짜 시계·브라우저 검증

| 입력과 조작 | 관찰 결과 |
|---|---|
| 이동 중인 침상형 로봇에 10 Hz로 1,800프레임. 값이 바뀌는 간격 0.1~0.5초 | 첫 프레임에서 이탈 감지. 180초 동안 `BED_EXIT` 1회, `BED_EXIT_CLEAR` 0회, `PAUSE` 이벤트·전송 각 1회. 같은 신호 패턴에서 관제가 만든 이벤트를 브라우저에 전달했을 때 팝업 1개, 경보음 요청 1회. |
| 이어서 연속 정상. 0.9초에 화면 재개와 ROS 서비스 재개 요청 | 두 경로 모두 이탈 해제 대기로 거절. 1.0초에 `BED_EXIT_CLEAR` 1회. 자동 재개 0회, 운영자 재개 뒤 `RESUME` 1회. |
| 같은 경보의 대상 배열 순서를 바꾸거나 동일 경보가 다른 경보 뒤에서 대기 | 여섯 종류 모두 중복 팝업과 추가 경보음이 없었다. 열린 창의 감지 시각이 갱신됐고 [확인] 버튼은 그대로였다. 다른 대상 경보는 별도로 남았다. |
| 경보 확인 뒤 이탈만 재반복, 다른 대상·다른 원인의 정지, 이후 같은 대상의 이탈 정지 | 반복과 무관한 정지는 팝업 0개. 같은 대상에 같은 원인의 새 정지가 오자 팝업 1개. 같은 정지 이벤트를 재전달해도 추가 팝업 0개. |
| 감시 끊김·복구를 5회 반복 | 동시에 대기하거나 열린 LOST는 최대 1개, 복구 직후 0개였다. 다른 경보가 앞에 있거나 뒤에 있어도 보존됐다. |
| 두 종류의 감시 경고를 29.999초와 30초 경계에서 반복 | 각 문구는 최초 1회, 30초에 다시 1회 표시됐다. 전달한 이벤트 8건은 모두 최근 운영 기록에 남았다. |

## 테스트와 빌드

워크스페이스 루트에서 ROS 2 Jazzy와 기존 Python 환경을 사용했다. 브라우저 시험은 임시 프로필의 headless Chromium에서 실제 화면의 이벤트 수신 코드와 [확인] 버튼을 실행했다.

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH="src/part1_ui_dashboard:src/part3_fleet_manager:$PYTHONPATH" \
  python3 -m pytest -p no:cacheprovider -q src/part1_ui_dashboard/test src/part3_fleet_manager/test
```

| 패키지 | 통과 | 실패 |
|---|---:|---:|
| PART 01 | 87 | 0 |
| PART 03 | 459 | 0 |
| 합계 | **546** | **0** |

두 대상 패키지의 `colcon build --symlink-install`도 성공했다. 기존 시험 10·25·35번과 운영 기록 시험의 정상 입력을 새 1초 기준에 맞췄다.
