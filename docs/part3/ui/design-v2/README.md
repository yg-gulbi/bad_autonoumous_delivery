# 관제 화면 v2 디자인 (11/19 팀장 확정)

원본은 Claude Design 캔버스 "B.A.D 관제 화면 새 방향"이고, 이 폴더의 `.dc.html` 5개가 그 캔버스의 원본 파일이다. 브라우저에서 바로 열리지는 않는다(캔버스 런타임 `support.js`가 필요). **인라인 `style` 값이 곧 사양**이니 색·간격·글자 크기는 여기서 그대로 가져온다. 이번 단계부터 화면 기준은 `ui/design/`(Figma 캡처)이 아니라 이 폴더다.

| 파일 | 화면 |
|---|---|
| `Main.dc.html` | 1. 종합 관제, 평상시 |
| `CorridorWait.dc.html` | 2. 종합 관제, 복도 반대 방향 대기 (11/18 상황) |
| `BedAlarm.dc.html` | 3. 침상 이탈 경보 팝업 |
| `Decision.dc.html` | 4. 결정 카드 팝업 (막힘 `BLOCKED`) |
| `Request.dc.html` | 5. 이송 요청 창. 동작 규칙은 아래 `<script>`의 `renderVals()`에 있다 |

## 1. 원칙

1. 평상시는 회색. 색은 문제가 있을 때만 쓴다.
   - 파랑 `#1D56C9`: 버튼과 선택 표시만. 로봇 색으로 쓰지 않는다.
   - 주황: 대기·양보.
   - 빨강: 안전 정지, 경보, Level 3 응급.
2. 한 사실은 한 곳에. 지금 무슨 일이 있는지는 **상황 줄** 하나에 쓴다. 같은 문장을 요약 칸·띠·로봇 카드·지도에 반복하지 않는다.
3. 로봇은 모양과 글자로 구분한다. A는 원, B는 둥근 사각형이고 둘 다 진한 바탕에 흰 글자다. 테두리 색이 상태다(정상 흰색, 대기 주황, 안전 정지 빨강). 지도 위 상태 글자는 정상이 아닐 때만 붙인다.
4. 복도에는 지금 사용 방향을 화살표로 그린다(DIRECTIONAL).
5. 카드 상자·그림자 없이 한 판을 구분선으로 나눈다. 그림자는 팝업에만 쓴다.

  - 모서리: 버튼 6px, 큰 선택 버튼 8px, 팝업 12px

## 3. 공통 틀

- **위쪽 막대** (어두운 색)
  - 로고 "B.A.D 병원 이송 관제"
  - 탭 5개: 종합 관제, 이송 작업, 환자 등록, 약품 운송 요청, 운영 기록
  - 오른쪽: 모드 표시, 담당자 입력, 시각
  - 왼쪽 사이드바는 없다.
- **명령 줄**
  - 왼쪽에 상태 다섯 가지: 관제 연결, 로봇 n대 연결, 침상 감시, 진행 작업, 배정 대기
  - 오른쪽에 [이송 요청](파랑 채움)과 [안전 정지 요청](흰 바탕, 빨강 2px 테두리, 굵게)
  - 정지 중이면 같은 자리에 [전체 재개]
- **상황 줄** (항상 있다)
  - 평상시: 회색 "이상 없음 / 로봇 2대가 정상 운행 중입니다."
  - 양보·대기·교착·점유 불명: 주황 + [판단 근거]
  - 침상 이탈·범퍼·침상 감시 끊김·연결 끊김: 빨강, 조건이 풀릴 때까지 남는다.
  - 여러 개면 가장 심각한 것 하나 + "외 n건".
- **없앤 것:** 요약 4칸

## 4. 종합 관제 (P1)

- **왼쪽**
  - 평면도 (최대 높이 460px)
  - 그 아래 복도 줄: 통과 로봇, 사용 방향, 대기 로봇과 위치. 대기 중이면 출발 조건 체크 4개.
  - 범례
- **오른쪽** (폭 380px)
  - 로봇 블록 2개: 역할 이름(크게) + "Robot A"(작게), 상태 표시, 임무 한 줄, 경로/지금/배터리/연결, 상태별 버튼
  - 상태 표시 색: 정상 회색, 대기 주황, 안전 정지 빨강 채움
  - 상태별 버튼은 `WEB_DB_DESIGN.md` 2.2 표를 따른다.
  - 아래에 작업 표 (진행 중 / 배정 대기 전환)
- **아래:** 최근 기록 3줄 + [전체 기록]

## 5. 팝업

- **경보 창**
  - 빨강 머리: 경고 아이콘, 제목, 경과 시간
  - 본문: 무슨 일인지, 로봇, 작업, 감지 시각, 관제 조치
  - 버튼: [확인](빨강 채움, 넓게), [경보음 끄기]
  - [확인]으로 창을 닫아도 상황 줄은 남는다.
- **결정 카드**
  - 주황 머리: 로봇 표시, 제목, 경과 시간
  - 본문: 근거 문장, 작업·멈춘 곳·장애물 분류, "어떻게 할까요?"
  - 선택지 버튼마다 한 줄 설명. 맨 아래 [나중에]
  - `default`가 있는 카드(교착)는 추천 선택지에 "추천"을 붙이고 남은 시간 막대를 그린다.
- **이송 요청 창**
  - 탭 3개(환자 이송 / 약품 운송 / 로봇 호출). 탭마다 가는 로봇 이름을 보여 준다.
  - 구역 버튼을 평면도 모양으로 놓는다: 위 D E F, 가운데 복도, 아래 A B C.
  - 누른 순서가 경로다. 환자는 출발·도착 2개, 약품은 1~6개, 호출은 1개.
    - 다시 누르면 빠진다.
    - 꽉 찬 상태에서 누르면 마지막 것을 바꾼다.
    - 탭을 바꾸면 그 탭의 최대 개수로 자른다.
  - 약품 탭: 정류장마다 약품 이름 칸과 [빼기]
  - 환자 탭: 환자 ID(필수), 이름(선택), 손목 태그(비활성, "QR 연동 후 사용")
  - 응급도 버튼 3개: 비응급 Level 1, 보통 Level 2, 응급 Level 3. 응급을 고르면 빨강.
  - 아래: 요약 문장 + [초기화] [요청 등록]. [요청 등록]은 다 채워야 켜진다.
  - P3 환자 등록과 P4 약품 운송 요청 페이지도 같은 폼 코드를 쓴다.

## 6. 로봇 이름과 역할 (11/19 팀장 결정)

| 논리 이름 | 화면 이름 | 표시 글자 | 맡는 작업 |
|---|---|---|---|
| `robot_a` | 침상형 이송 로봇 | A (원) | 환자 이송 |
| `robot_b` | 약품 운송 로봇 | B (둥근 사각형) | 약품 운송, 로봇 호출 |

- 배정은 역할 고정이다(`assignment.mode: ROLE`).
- 작업 종류 표시명은 "물품 전달" 대신 "약품 운송"을 쓴다. 내부 type `MED_ROUND`는 그대로다.
