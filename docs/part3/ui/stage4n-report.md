# 4N 현장 재현과 검증

복도가 비어도 출구의 두 로봇 사이에 출발 간격이 생길 때까지 기다리도록 했다. 15:02와 15:03 상황을 각각 가짜 시계로 재현한 결과, 두 경우 모두 근접 정지가 0회였다. 출발과 도착 순서는 실제로 보낸 명령과 두 자리의 위치로 판단한다. [결정 D-40~42](../DECISIONS.md)

## 현장 장면

| 재현 | 관제의 판단과 실제 명령 |
|---|---|
| 15:02:26, 복도를 빠져나가는 침상형과 출구 앞의 약품 로봇 | 복도 해제 뒤 간격이 0.499 m일 때 침상형에 정지 0회, 약품 로봇에 MOVE 0회. 간격이 0.91 m로 벌어지고 기존 복도 경쟁 대기 시간이 끝나자 약품 로봇에 `MOVE D` 1회. |
| 15:03:38, 수술실(C) 1번에서 출발 요청 중 다른 로봇이 2번으로 접근 | 침상형에 `MOVE C2`. 복도 해제 후 두 로봇 간격이 0.584 m여도 1번의 약품 로봇은 출발을 기다렸다. 2번 도착 후에는 ‘출구 막힘 대기’가 이어졌다. 침상형이 2번을 떠나고 간격도 확보되자 약품 로봇에 `MOVE D` 1회. |
| 출발 로봇이 먼저 구역을 나오는 순서 | 도착 로봇은 수술실(C) 두 자리에서 모두 2 m 이상 떨어진 곳에서 PAUSE를 받았다. 출발 로봇이 반경을 벗어난 뒤 RESUME를 받았다. 인접한 조제실(F) 도착 보고가 먼저 와도 실제 위치가 반경 안이면 기다렸다. |
| 먼저 보내기가 실패한 정면 교착 | 두 로봇이 주행 중 정지한 뒤 한 대만 재개했다. 거리가 0.52 m에서 0.51 m로 줄자 다시 정지했다. 두 선택 경로 모두 다음 카드는 한 장이었다. [되돌아가기 · 추천]을 고르자 후발 로봇이 CANCEL 확인 뒤 원래 구역으로 MOVE했고, 0.9 m를 확보하자 상대 로봇이 재개했다. |

현장 기록에 없는 중간 좌표와 수신 간격은 시험 입력으로 구성했다. [가짜 시계 재현 시험](../../../src/part3_fleet_manager/test/test_4n.py)

## 설정과 표시

| 구역 표시 | 1번 자리 → 가장 가까운 복도 입구 선분과 2번 자리의 거리 | 출구 막힘 설정 |
|---|---:|---|
| 응급실(A) | 0.466 m | 켬 |
| 102호 병실(B) | 0.948 m | 끔 |
| 수술실(C) | 0.398 m | 켬 |
| 간호 스테이션(D) | 0.492 m | 끔 · 경고 |
| 101호 병실(E) | 0.909 m | 끔 |
| 조제실(F) | 0.229 m | 켬 |

- 이름은 설정에서 한 번 읽는다. 지도, 요청 목록, 로봇 블록, 작업 표, 카드와 기록에서 “수술실(C) 2번 자리”, “102호 병실(B) 출입”으로 보인다. 예전 DB의 문장도 조회할 때 바꾼다. DB의 정류장은 `C`, PART 04 목적지는 `C2`로 검증했다.
- 출입 반경은 `resources.zone_arrival_clear_m: 2.0`이다. 자리 중심들까지 거리 중 최솟값을 쓴다. 도착 쪽은 기존 여유 거리 `clear_margin_m` 0.20 m를 더해 바깥에서 정지를 요청한다. 한쪽이 먼저 진입하면 위치가 경계에서 흔들려도 그 순서를 유지한다. 같은 tick에 출발 요청이 둘이면 첫 MOVE를 보낸 뒤 두 번째 로봇의 조건을 다시 검사한다.
- 출발 전 간격은 기존 `proximity_resume_m` 0.9 m를 쓴다. 언독 중이나 정지 응답 대기 중인 상대도 움직일 수 있는 것으로 취급한다. 새 근접 정지의 예외는 양쪽의 최신 위치가 있는 경우에만 적용한다. 0.5초를 덮는 표본에서 거리가 감소하지 않고 마지막 측정에서도 증가해야 한다. 이미 걸린 정지는 거리 추세만으로 해제하지 않는다.
- 마주 봄은 로봇 쌍에 표시한다. 추천은 현재 구간의 첫 MOVE 전송 시각을 기준으로 정하고, 같은 시각에는 실제 전송 순서를 쓴다. 카드에는 자동 선택 시간이 없다.
- 설정이 꺼진 구역의 경고 기준은 `slot_stop_m + 0.10`으로 현재 0.55 m다. 격리 mock 두 대로 시작 로그와 읽기 전용 preflight에서 간호 스테이션(D)의 0.49 m 경고를 각각 확인했다. 두 로봇의 연결 판정은 모두 OK였다.
