## 3. 남은 일

### 3.1 코드 정리 (11/19 구조 검토 결과)

외부 검토(`part3_structure_review.pdf`, 11/19)가 짚은 구조 문제를 위험도 순으로 나눴다. 이유는 `DECISIONS.md` D-20.

| 시점 | 할 일 | 위험 |
|---|---|---|
| 지금 (실제 시험과 병행 가능) | 로봇 ID·동점 순서(`"robot_a"`·`"robot_b"` 하드코딩 4곳)를 설정으로, `fleet_core._acks_seen` 상한, 쓰이지 않는 `blocked_by`·`ICD_GOAL_POSE` 제거, 끝난 임무 표시 건수 20을 설정으로, 반복문 변수 `kind` 재사용 정리 | 낮음 |
| 실제 시나리오 1·2 통과 뒤 | `fleet_core`의 멈춤·장애물 판단(약 90줄)을 `stall` 쪽으로 옮기기, 이벤트 기록을 `resource_manager.record()`에서 떼어 별도 기록부로 | 중간 (범위 한정) |
| 시연 준비가 끝나고 시간이 남으면 | "판단 모듈은 결과만 돌려주고 서로 부르지 않는다" 전면 개편 (직접 호출 약 95곳) | 높음 (이벤트 순서·같은 tick 연쇄가 바뀜) |

- 같은 검토가 다음에 보겠다고 한 **교착 흐름이 현장(Nav2 정체 → 화면 → 결정 카드)과 맞는지**는 단계 4 실제 시험에서 확인한다.

### 3.1a 복도 마주침 (11/18 실제 시험)

- 원인: 양보 규칙이 "누가 설지"만 정하고 "어디서 설지"는 안 정한다. 복도 폭 약 0.9 m에 TurtleBot4(지름 약 0.34 m) 두 대는 비켜 갈 틈이 거의 없다.
- 다음 시험: 복도 한 대씩(`corridor.mode: EXCLUSIVE`). 저장소 기본값은 그대로 두고 실행 때 설정 사본을 넘긴다 (`real.launch.py config_file:=…`). 저장소 기본값을 바꾸면 복도 양보 테스트 31개가 깨진다.
- 그 뒤: 방향별 공유 (같은 방향만 같이 들어가고, 반대 방향은 복도 밖·방 안에서 기다림). 테스트가 기본 설정 대신 자기 모드를 직접 정하도록 고친다. 이미 둘 다 복도 안이면 낮은 쪽이 대피 지점으로 물러나야 하는데, PART 04가 구역 이름(A~F)으로만 보낼 수 있어 대피 지점 목적지를 요청해야 한다 (R5 후보).
- 범퍼: 관제 PC에 `ros-jazzy-irobot-create-msgs`가 깔려 있는지, `/robotN/hazard_detection`이 관제 PC에서 보이는지 확인한다. 로봇 스스로 범퍼에 멈추는지는 PART 04에 확인한다.
