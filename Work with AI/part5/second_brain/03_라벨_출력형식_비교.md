# 03. 네 방법 라벨·출력 형식 비교

## 1. 확인 범위

- 로컬 코드: `methods/bed_exit_core.py`
- Roboflow 원본: `raw/data.yaml`과 848개 YOLO label
- 공식 문서: Ultralytics COCO pose·YOLO label format·segmentation result, MediaPipe Tasks Vision pose result·running mode
- 버전: Ultralytics 8.4.210, MediaPipe 0.10.21

## 2. 결론 비교표

| 방법 | 사전학습 라벨 의미 | 실제 추론 출력 | Part 5가 쓰는 geometry | 최종 raw Bool |
|---|---|---|---|---|
| Detection | COCO `person` box | `xyxy`, confidence | 선택된 사람 box | ROI 밖 box 면적 비율 > threshold |
| Segmentation | COCO `person` instance mask | `(N,H,W)` mask + box | 선택된 사람 mask | ROI 밖 mask 픽셀 비율 > threshold |
| YOLO Pose | COCO person 17관절 | `(N,17,3)` pixel x/y/confidence + box | 공통 13관절 | 신뢰 가능한 관절 하나 이상 ROI 밖 |
| MediaPipe Pose | 33 landmark pose | pose별 normalized x/y/z/visibility/presence | 공통 13관절, confidence=`min(visibility,presence)` | 신뢰 가능한 관절 하나 이상 ROI 밖 |

공통 13관절은 nose, 좌우 shoulder·elbow·wrist·hip·knee·ankle이다. 구현에 이름과 양쪽 index를 함께 가진 `COMMON_LANDMARKS`를 추가해 문서와 코드의 index drift를 차단했다.

## 3. Roboflow 라벨 해석

```text
0 = bed_exit
1 = hospital_bed
2 = in_bed
row = class_id x_center y_center width height
```

로컬 848장의 조합은 `bed_exit`만 213, `bed_exit+hospital_bed` 55, `hospital_bed`만 73, `hospital_bed+in_bed` 51, `in_bed`만 456이다.

중요한 충돌: Roboflow class id 0 `bed_exit`는 COCO class id 0 `person`과 의미가 다르다. 숫자 id만 보고 직접 연결하면 잘못된 모델이 된다.

## 4. 확정 결정

- 원본 `bed_exit/in_bed` state 라벨은 보존한다.
- 현재 네 사전학습 방법에는 state 라벨을 모델 입력으로 사용하지 않는다.
- `bed_exit/in_bed`는 POC 표본 층화와 provisional expected Bool에만 사용한다.
- 네 방법 비교는 사람 box/mask/keypoint를 추출한 뒤 같은 단일 ROI Bool로 변환한다.
- 향후 사람 영역 학습이 필요하면 원본을 덮어쓰지 않고 derived dataset에서 `bed_exit`와 `in_bed` box를 시각 검수 후 `person`으로 병합한다.
- `hospital_bed` box는 정적 POC ROI로만 사용하며 배포 ROI로 승격하지 않는다.

따라서 통화의 “in/out 라벨을 제거하고 사람 영역만 사용” 후보를 채택하되, 삭제가 아니라 원본 보존 + derived person dataset 분리 방식으로 적용한다.
